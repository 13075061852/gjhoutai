# 框架、UI 与安全检查（第一轮）

## 范围与结论

保留 React 18 + Vite + TypeScript + legacy 功能按需加载，不在同一次变更中重写所有业务页面。此次建立公共 UI 规范、错误恢复和 Worker 请求安全边界，并修复已有代码中可复现的问题。不是全量渗透测试，也不是所有页面已经逐屏完成视觉验收。

## 公共 UI 与架构

- `src/styles/foundation/base.css`：单一字体栈；12/13/14/16/20px 字号；400/500/600 字重；4px 间距尺度；32/40/44px 控件高度。
- `src/styles/components/design-system.css`：登录、业务页和弹窗的公共字体、表单、常用按钮、下拉选项、键盘焦点、禁用态及系统减少动态效果偏好。表格紧凑控件、图标按钮、画布工具保留专用布局，避免全局强制宽高。
- `src/components/ui/Button.tsx`：可复用按钮，默认 `type="button"`，支持主操作/危险操作、尺寸及 loading 禁用；登录和改密页已使用。
- `src/components/ErrorBoundary.tsx`：React 渲染失败时提供恢复入口，不把异常堆栈直接显示给用户。
- `worker/security.ts`：集中处理写请求来源校验、JSON 大小/类型校验、公共存储键校验及下载文件名编码。
- `tsconfig.worker.json`：新增独立 Worker 严格类型检查，不再只依赖前端 tsc 和 Worker 打包。
- `npm run check`：锁文件检查 → UI 规范检查 → Worker 类型检查 → 测试 → 前端生产构建。

新增页面应优先组合 React 公共组件及现有 `.ui-field`、`.ui-toolbar`、`.ui-panel`、`.ui-dialog-*`，不要再复制一套按钮和下拉框规则。后续按业务域拆分 `business-pages/index.ts`，逐步将 DOM 拼接迁移为 React 组件，而不是在公共 CSS 中不断堆叠高优先级覆盖。

## 本轮修复

### 安全

1. **CSRF**：原先只有 CORS 响应头，不能阻止 Cookie 写请求执行。现在在处理请求前校验 Origin；允许 API 同源及 `CORS_ORIGINS` 精确配置的来源，拒绝不可信来源和 `null` 来源。无 Origin 的非浏览器 API 调用仍可使用既有会话认证。
2. **用户隔离绕过**：通用 `/api/state/` 不能再直接访问 `users/<其他用户>/...`；拒绝路径分隔符、控制字符等非法键。
3. **R2 命名空间越权**：通用 blob 接口仅允许前端实际使用的 `spectrum`、`cutout`，不能绕过头像、个人识别历史和报告专用接口的权限检查。
4. **首次改密绕过**：用户管理和头像接口补充 `mustChangePassword` 校验。
5. **密码与旧会话**：改密时保留当前会话、撤销其他会话；管理员重置密码时撤销目标用户全部会话。密码更新和撤销使用 D1 batch。修正原 SQL 中“目标 id 与自身比较总为真”导致被重置账户未被强制改密的问题。
6. **输入校验**：登录及用户信息字符串类型/长度验证；JSON 解析前按实际字节计数限流，不能只靠 Content-Length；畸形 JSON、URI 和 Cookie 不再直接抛出未处理异常。
7. **共享权限与日志**：非管理员不能写共享页面权限或删除全局调用日志；新增调用记录的身份由服务端会话生成，不能改写其他用户已有记录。
8. **响应与代理**：统一受控错误响应；LiblibAI 代理禁止跟随重定向并设置超时；中文文件名使用 RFC 5987 编码，避免 HTTP header 非 ASCII 导致下载失败。
9. **静态页面头**：新增 Pages `_headers`，阻止被第三方页面嵌入，设置 nosniff、Referrer-Policy 及最小 CSP。没有强行加入会破坏动态 CDN/第三方模型接口的 script-src/connect-src 白名单。
10. **依赖**：升级 Vite、Wrangler、undici、ws 及相关传递依赖。安装保持官方源和精确直接版本；未使用 `npm audit fix --force`，未全局允许安装脚本。

### 功能与生命周期

- 登录和首次改密请求失败后恢复按钮状态，显示可读错误，避免永久 loading。
- 登录态验证/页面初始化失败有重试入口，不再无限停在启动壳。
- 强制刷新账户时绕过短期缓存；过期的 `/me` 请求不能在注销后重新填充旧缓存。
- 服务器未确认退出时不伪装为注销成功；成功后重载以丢弃 legacy 模块内存状态。
- 清理账户菜单 document 事件，补 Escape 操作，处理头像请求异常和迟到的初始化结果。
- 登录粒子效果仅在有粒子时调度动画帧，并响应系统减少动态效果设置。
- 自定义下拉框尊重 select/option/optgroup 禁用态，补充标签关联、input/change 事件、Tab/Escape/Home/End、跳过禁用项、滚动关闭和视口定位；原生多选不再错误转换成单选。
- 修正 CSS 测试读取方式：Vitest 默认 CSS stub 会令部分 `?raw` 导入变成空串，使原先的否定断言出现假通过；改为读取实际文件。
- 云端读取失败不再被当成“远端没有数据”，从而避免删除本地业务数据或把本地旧权限重新写入云端；取消的初始化不再应用迟到响应。

## 验证方式

```bash
npm install
npm run check
npm audit
npx wrangler deploy --dry-run
```

最终结果：60 个测试文件、340 项测试通过（原基线 54 个文件、299 项）；`npm run check`、`npm audit`（0 漏洞）、Worker 部署 dry-run 和 `git diff --check` 均通过。

新增测试覆盖模拟 DOM 下拉交互、认证错误恢复、会话缓存竞态、云同步失败，以及 Worker 来源检查、内部路径隔离、改密撤销、非法输入、日志身份和下载文件名编码。DOM 测试使用 happy-dom，Worker 单元测试使用模拟 D1/R2，不等同于真实浏览器或生产数据库集成测试。

## 部署注意

- 本轮没有部署线上或执行生产迁移。前端与 Worker 都需要发布，后端修复不会因为只更新网页而生效。
- 确保实际前端域名在 `CORS_ORIGINS` 中，否则新增校验会拒绝跨域写入。不要配置 `*` 或 `null`。
- 通用 blob 接口不再接受任意 namespace；若有仓库外部调用方，发布前确认其调用方式。
- Node.js 建议使用当前受支持的 Node 24；本次验证环境为 Node 24.20.0 / npm 12.0.2。
- npm 对 esbuild/workerd 安装脚本的阻止警告仍保留。这是安全策略，不是漏洞或构建失败；只有实际需要时，审核具体脚本后逐包批准。

## 尚需继续完成的检查

1. **逐屏视觉验收**：登录、仪表盘、库存、订单、配方、配置、物性/图谱、识别/报告、媒体/AI 页，在深浅色及 1440/980/720/390px 下检查实际排版、长文本、弹窗、表格和按钮状态。本轮没有真实浏览器逐页截图对比；旧页面高优先级/内联样式仍需按页面迁移。
2. **业务级授权细化**：共享业务状态目前仍使用较粗的 `state:write` 权限，页面隐藏不能当作服务端权限。需按订单、配方、生产、库存等业务资源定义写权限，并设计并发版本检查，避免整块状态最后写入覆盖。
3. **大文件与外部内容**：PDF/form-data、大型备份、普通 blob 上传及遗留远程导入仍需统一的流式大小限制、文件签名校验和孤立文件清理；此次 JSON 限制不能替代这些检查。
4. **客户端数据治理**：进一步梳理跨账户 localStorage/IndexedDB 缓存归属和清理策略，迁移第三方 API 密钥与签名到后端；动态 CDN 脚本、Markdown/HTML 渲染需继续专项检查。
5. **生产集成与并发**：在测试环境验证真实 D1 batch、R2、Cookie 跨域行为、管理员改密流程；登录限速并发更新、首次管理员初始化竞态仍需专项加固。

`npm audit` 的 0 漏洞仅代表当前依赖数据库未报告已知漏洞，不代表应用已不存在安全风险。
