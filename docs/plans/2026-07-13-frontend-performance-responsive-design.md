# 前端性能与响应式统一设计

## 目标

在不改变现有业务数据结构和用户操作流程的前提下，降低首屏加载与页面切换成本，统一桌面、平板、手机布局规则，并收敛按钮、表单、工具栏、表格、分页和弹窗的视觉实现。

## 现状与问题

- `src/legacy/features/business-pages/index.ts` 超过 400 KB，集中承载多个业务页面的渲染、状态和事件处理。
- `src/styles/pages/business-pages.css` 超过 200 KB；`responsive.css` 又在入口最后加载，页面专用规则容易被二次覆盖。
- 全部页面 CSS 从 `styles.css` 同步引入，未访问页面的样式也进入初始 CSS。
- 响应式断点分散在十余个数值上，手机、平板和窄桌面之间存在规则重叠。
- 控件高度、圆角、间距和弹窗结构大量使用硬编码值，形成多套近似组件。

## 设计方向

采用渐进式基础设施重构，不重写业务功能：

1. 在基础层定义尺寸、间距、断点语义、控件和弹窗令牌。
2. 用共享 `.ui-*` 原语统一按钮、输入框、工具栏、弹窗、表格和分页；旧类名通过组合选择器逐步兼容。
3. 响应式规则遵循桌面默认、平板 `<= 1200px`、紧凑平板 `<= 980px`、手机 `<= 720px`、小手机 `<= 480px`，只有确有内容约束的页面允许局部断点。
4. 应用壳响应式只处理壳层；页面响应式留在页面文件，禁止全局文件重复改写具体业务组件。
5. 将大业务模块按页面域拆分，保留共享状态和统一事件入口；页面代码通过动态导入按需加载。
6. 将非首屏页面 CSS 从全局入口移出，随功能模块加载；基础、壳层和共享组件 CSS 保持首屏加载。

## 兼容约束

- 保留现有 `localStorage` 键、云同步格式、DOM 数据属性和权限判断。
- 不引入渐变色；现有纯色主题继续由 CSS 变量控制。
- 不依赖浏览器验证作为交付门槛，使用测试、类型检查、构建和静态审计验证。
- 新文件使用 UTF-8；构建产物、缓存、日志、环境文件不得提交。

## 验收指标

- 统一响应式断点不再由 `responsive.css` 覆盖页面专用组件。
- 共享控件具备一致的 36/40/44px 尺寸、圆角、焦点态和禁用态。
- 弹窗遮罩、卡片、标题、正文、底部操作区使用统一结构令牌。
- 重复选择器与硬编码视觉值显著下降，并提供静态审计脚本防止回退。
- `business-pages` 生产包和初始 CSS 被拆分，页面切换按需加载对应代码/样式。
- 全量测试、类型检查、图标映射检查、生产构建和 `git diff --check` 通过。

## 当前实施指标

- 全局初始 CSS：约 526 KB 降至约 73.5 KB。
- 默认仪表盘 CSS：无需加载 134.9 KB 的完整业务构建样式，仅加载 7.7 KB 独立样式。
- 默认仪表盘 JS：不再加载约 258 KB 完整业务运行时，仅加载约 15.7 KB 仪表盘代码。
- 完整业务 CSS：删除重复仪表盘和孤立规则后降至约 134.9 KB 构建产物。
- `business-pages/index.ts`：拆出仪表盘、AI 查询、档案和权限职责后由约 400.5 KB 降至约 368.3 KB 源码；详细业务运行时仅按需加载。
- 渐变声明：40 处降为 0，并由 `npm run check:ui` 阻止回退。
- 页面样式：12 个非首屏页面改为随功能模块按需加载。
- 聊天与 AI 管家：改为主页面渲染后异步初始化，不阻塞导航首屏。
- 生命周期：导航重启会刷新 DOM 引用并清理页面级监听器、计时器与初始化标记，避免重复绑定拖慢后续响应。
- 最终生产构建：3255 个模块，10.51 秒完成；入口 JS 78.7 KB，入口 CSS 73.5 KB。
