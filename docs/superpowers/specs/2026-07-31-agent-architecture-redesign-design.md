# Agent 调度架构重构设计

日期：2026-07-31

## 背景

当前聊天入口把意图识别、项目上下文选择、技能执行、联网搜索、图片处理、模型调用、状态展示和异常收尾集中在同一条流程中。普通问候也可能因为当前页面存在而被标记为需要项目上下文，继而进入项目 Agent 循环。多个串行模型请求各自拥有较长超时，且部分前置异步操作位于统一异常边界之外，最终表现为界面长时间停留在“正在理解问题”。

本次采用完整架构重构，不保留旧技能调用协议。现有项目数据能力、联网搜索、图片分析、图片生成和模型提供商能力会迁移到新协议，而不是删除或缩减。

## 目标

- 普通聊天直接调用一次聊天模型，不读取项目能力地图。
- 明确的单工具任务直接执行，不经过多轮 AI 规划。
- 只有复杂项目任务进入受约束的规划器。
- 所有执行路径都有明确状态、期限、取消传播和终态。
- 查询自动执行；新增、修改和删除必须得到用户确认。
- 展示执行步骤、调用能力和关键结果，不展示模型内部思维。
- 所有工具使用统一、可校验、可审计的新协议。
- 迁移期间保持现有业务能力和旧记录可用。

## 非目标

- 不更换现有业务数据源。
- 不改变用户已经配置的模型提供商和密钥存储方式。
- 不在本次重构中重新设计整个聊天界面。
- 不展示或持久化模型的内部思维过程。
- 不为无关业务页面进行顺带重构。

## 总体架构

新 Agent 核心由六个模块组成：

### IntentGateway

负责规范化输入并识别任务类型：

- `chat`：普通聊天、问候、写作和解释。
- `single_tool`：目标明确、可由单个工具完成的查询。
- `complex_agent`：需要分解步骤或组合多个项目数据源的任务。
- `web_search`：需要实时或外部资料。
- `image_analysis`：分析用户或项目中的图片。
- `image_generation`：生成图片。

本地确定性规则优先处理明确意图。只有无法可靠分类的输入才调用轻量分类模型。当前页面只作为消歧信息，不能单独把普通聊天升级为项目任务。

### AgentPlanner

仅接收 `complex_agent`。规划器根据已注册工具及其协议生成结构化计划，每一步包含工具 ID、输入、目的和依赖。规划器不能执行工具、不能调用未注册工具，也不能绕过权限策略。

### ToolRegistry

集中登记工具定义、版本、权限、输入输出结构、超时、重试和执行适配器。项目数据、联网、图片和助手能力均通过同一注册表提供。

### ExecutionEngine

以显式状态机执行直接任务或复杂计划，负责依赖顺序、参数校验、取消传播、期限、重试、确认暂停、结果收集和终态收尾。

### PolicyEngine

根据工具权限等级决定是否允许执行：

- `read`：自动执行。
- `create`、`update`、`delete`：生成操作预览并等待用户确认。

确认必须绑定一次性确认 ID、运行 ID、工具调用和幂等键。参数变化后旧确认立即失效。

### ResponseComposer

根据结构化工具结果和证据生成最终回答。普通聊天直接返回模型回答；项目任务只能基于实际工具证据描述数量、名称、状态和操作结果。界面展示高层步骤及关键结果，不展示内部思维。

## 统一工具协议

每个工具定义必须包含：

- `id`：稳定且唯一的工具 ID。
- `version`：协议版本。
- `title`、`description`、`category`：用途和分类。
- `riskLevel`：`read`、`create`、`update` 或 `delete`。
- `inputSchema`、`outputSchema`：可运行时校验的数据结构。
- `timeoutMs`：工具执行期限。
- `maxRetries`：允许的自动重试次数。
- `idempotent`：是否可安全重试。
- `supportsAbort`：是否支持取消。
- `handler`：执行适配器。

工具调用包含运行 ID、步骤 ID、工具 ID、协议版本、输入、期限和幂等键。工具结果统一为：

- `status`：`success`、`error`、`cancelled` 或 `timeout`。
- `message`：面向用户的简短摘要。
- `data`：结构化业务结果。
- `evidence`：最终回答可引用的事实证据。
- `actions`：允许用户继续触发的操作。
- `diagnostics`：经过脱敏的错误信息。

规划器输出和工具输入必须先通过协议校验。非法计划不会进入执行器，而是返回可诊断失败。

## 状态机

每次请求创建独立的 `AgentRun`。主要状态转换为：

`routing -> planning | executing -> awaiting_confirmation -> composing -> completed`

任意活动阶段可以进入：

`failed | timed_out | cancelled`

约束如下：

- 每个活动状态必须有明确入口、退出条件和期限。
- 所有异步工作从请求开始即位于统一的 `try/catch/finally` 内。
- `finally` 必须释放忙碌状态、取消计时器并恢复输入能力。
- 取消信号从运行上下文传播到分类器、规划器、工具和回答生成器。
- 等待用户确认时暂停运行期限；确认后从持久化计划恢复。
- 所有路径必须进入终态，禁止无限保留 pending 消息。

## 超时与重试

- 明确意图使用本地规则立即分类。
- 模糊意图分类模型默认 12 秒，失败后采用本地保守结果。
- 复杂规划默认 45 秒。
- 查询工具默认 30 秒，可按工具定义覆盖。
- 最终回答生成默认 60 秒。
- 只有声明为幂等的查询工具在临时网络错误时自动重试一次。
- 写操作不进行无幂等保障的自动重试。
- 超时信息必须说明失败阶段，并提供重试或缩小范围建议。

## 写操作确认

新增、修改或删除执行前生成确认预览，至少包括：

- 操作名称和目标对象。
- 关键输入参数。
- 预计影响范围。
- 风险说明。
- 确认有效期。

运行进入 `awaiting_confirmation` 后不会执行写工具。用户确认时，执行器校验运行状态、确认 ID、工具参数摘要、有效期和幂等键。重复确认只能返回同一次执行结果，不能重复写入。

## 进度与审计

用户可见步骤包含阶段名称、正在调用的能力、耗时和关键结果，例如“正在查询库存”“已读取 12 条记录”“等待确认修改 1 条配方”。不展示内部思维、完整系统提示词、密钥或原始请求头。

审计记录使用带版本号的 `AgentRunRecord`，保存路由结果、步骤状态、工具 ID、耗时、脱敏错误、确认记录和最终状态。旧聊天记录和旧调用日志保持只读兼容，新记录使用独立存储键，避免覆盖旧数据。

## 代码边界

新核心放在独立的 Agent 运行时目录中，至少拆分为：

- 路由与意图规范化。
- 运行状态和状态转换。
- 规划器协议及校验。
- 工具注册表和工具类型。
- 权限与确认策略。
- 执行器。
- 回答合成。
- 审计记录。

聊天功能只负责收集输入、提交运行、渲染进度、处理确认和显示结果。业务模块只通过工具适配器暴露能力，不依赖聊天界面。

## 迁移策略

1. 建立新协议、状态机、执行器和测试，不连接现有聊天入口。
2. 将只读项目能力迁移为新工具并加入契约测试。
3. 迁移联网搜索、图片分析和图片生成能力。
4. 迁移新增、修改和删除工具，接入确认与幂等机制。
5. 用新 Agent 内核替换聊天入口的旧路由和项目循环。
6. 保留短期只读兼容适配层，确认所有调用方迁移后删除旧协议。

迁移不能静默减少现有能力。每项旧技能必须有对应新工具、明确替代说明，或在删除前得到单独批准。

## 测试策略

### 单元测试

- 意图路由和当前页面消歧。
- 状态转换合法性。
- 工具协议输入输出校验。
- 权限判定和确认失效。
- 超时、取消和重试策略。
- 幂等键及重复确认。
- 证据约束和最终回答选择。

### 集成测试

- “早”等普通问候只调用一次聊天模型，不读取项目能力。
- 明确查询直接调用单个只读工具。
- 复杂项目任务规划并按依赖执行多个工具。
- 写操作在确认前不执行，取消后不执行。
- 工具失败、规划失败、回答失败和取消均进入正确终态。
- 任意失败后忙碌状态和输入框恢复。
- 旧记录可读，新记录不会覆盖旧数据。

### 工具契约测试

每个迁移工具必须验证协议版本、参数校验、权限级别、超时、取消、成功结果和失败结果。

### 完成验证

运行聚焦测试、完整测试、类型检查和生产构建。不启动浏览器；视觉和实际交互效果由用户自行检查。

## Git 与生成物规则

继续使用现有 `.gitignore` 排除 `node_modules/`、`dist/`、`coverage/`、Wrangler 状态、构建缓存、日志、环境文件和编辑器文件。重构中新增的临时运行记录、调试转储或本地确认快照必须加入忽略规则，不能提交密钥、业务隐私数据或生成产物。

提交应按“核心协议与状态机、工具迁移、聊天接入、清理旧实现”分组，避免把工作区中无关改动混入提交。
